# Журнал типовых инцидентов

| Инцидент | Наблюдаемый признак | Первичный источник диагностики |
|---|---|---|
| Неиспользуемая переменная | Красная проверка `pylint` в PR | Журнал шага Static analysis |
| Недостаточные права публикации | `build` успешен, `deploy` не получает OIDC-токен | Журнал `deploy-pages` и блок `permissions` |
| Битая ссылка | `mkdocs build --strict` завершается ошибкой | Журнал шага Build documentation |
| Старая версия после успешного деплоя | Зелёный workflow, прежнее содержимое в браузере | URL окружения, время публикации, кэш браузера |

## Правило разбора

В разборе указываются симптом, затронутый компонент, доказательство из журнала,
причина, исправление и проверка восстановления. Ответ «перезапустил и заработало»
без установления причины неполон.

### Инцидент 1: неиспользуемая переменная

Симптом: красная проверка `pylint` в PR.
Затронутый компонент: журнал шага Static analysis.
Доказательство: сообщение о неиспользуемой переменной в src/static.py.
Причина: ненулевой код возврата Pylint из-за неиспользуемой переменной.
Влияние: невозможность выполнить слияние и прямой push в ветку main; новая версия не опубликована.

### Инцидент 2: недостаточные права публикации

Симптом: `build` успешен, `deploy` не получает OIDC-токен
Затронутый компонент: журнал `deploy-pages` и блок `permissions`.
Доказательство: сообщение об отсутствии разрешения `id-token: write` в шаге `Deploy To GitHub Pages`.
Причина: отсутствие разрешения `id-token: write` в блоке `permissions`.
Влияние: новая версия не опубликована; предыдущая версия сайта остаётся доступной.

### Инцидент 3: битая ссылка

Симптом: failed workflow Publish documentation после merge.
Затронутый компонент: сборка MkDocs, задание build.
Доказательство: сообщение о битой ссылке на docs/recovery.md.
Причина: ссылка указывает на несуществующий файл; --strict превращает предупреждение в ошибку.
Влияние: новая версия не опубликована; предыдущая версия сайта остаётся доступной.
